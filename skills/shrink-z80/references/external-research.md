# External Research

Use live search to discover size mechanisms that static catalogs miss. Browse
from a local question; do not trawl a familiar source list or treat web claims
as byte evidence.

## Trigger Gate

Research when:

- the user requests deep, underground, forum, blog, repository, or demoscene
  mining;
- a broad SAFE pass cannot meet the byte/resident goal;
- codec, decoder, compiler, linker, startup, ABI, or target behavior can change
  the top candidate;
- a repeated generated-code shape needs issue/commit/rule archaeology;
- an unusual renderer, loader, sound engine, bank scheme, or sizecoding pattern
  has no adequate local explanation.

Skip research when current source and fresh artifacts already prove the best
path.

## Query From Evidence

Build queries from exact local facts:

- emitted instruction sequence, helper symbol, map section, compiler version,
  flags, CRT/clib, or peephole rule;
- asset type/size/entropy, current codec/decoder, workspace, and load-time
  constraint;
- target/model, memory address, paging state, screen layout, ISR/DI window, or
  ROM dependency;
- code fragment or algorithm plus `bytes`, `sizecoding`, `decoder`,
  `postmortem`, `issue`, `commit`, `source`, or the community's own vocabulary.

Repeat useful queries in English and relevant Spanish, Polish, Russian, Czech,
or other regional terms. Exact-code search often outperforms generic advice.
Repeat finalists with `bug`, `wrong`, `regression`, rejected/closed issues,
clone/model names, interrupts, and hidden decoder/workspace costs. Search only
minimal normalized signatures; never upload private source or identifiers.

## Source Corridors

Diversify; these are categories, not an allowlist:

- compiler/assembler/linker source, tests, issues, commits, release notes, and
  generated examples;
- codec repositories, reference decoders, benchmark harnesses, forks, and
  integration issues;
- small game/demo repositories, build tools, asset generators, disassemblies,
  release NFOs, and size histories;
- regional forums, mailing-list archives, personal blogs, old web mirrors, and
  calculator/MSX/CPC/SMS communities;
- emulator tests and real-hardware measurements for target-sensitive tricks.

Follow authors, citations, forks, related issues, and archived dead links. The
first page is discovery, not completion.

## Transfer Card

```text
Question / exact query:
URL / access date / source revision / source class:
Technique or measured claim:
Original CPU/target/tool version:
Preconditions and hidden costs:
Current project anchor:
Local net-byte formula:
Behavior/ABI/timing checks:
Status: SEED | EXTERNALLY CORROBORATED | LOCALLY APPLICABLE | REJECTED
```

Prefer an implementation/test artifact plus independent corroboration. Never
copy fixed decoder sizes, cycle counts, or savings into the report without
counting the exact version linked or benchmarked by the current project.

## Useful Research Lanes

- CRT/startup/library deletion and compiler codegen regressions;
- data representation, shared suffix/prefix, build-time generation;
- codec/decoder Pareto tradeoffs on the project's actual assets;
- screen/sprite/scroll/dirty redraw and generated blitters;
- banks/overlays/loaders/IM2/ROM reuse under the exact target matrix;
- sound-player specialization and packed event streams;
- page-local tables, RST amortization, SMC/SP/flag tricks after SAFE work.

## Efficient Parallel Use

For deep work, a `research-scout` may search independently while local lanes
measure the immutable baseline. Give it bounded questions and a project
signature, not the repository. It returns at most five transfer cards ranked
by potential net impact and verification cost.

Budget at most three cards for Standard and five total for Deep; count and
verify only the two or three that can alter the size frontier.

Without a delegate, research the single top unresolved mechanism, reassess, and
expand only if it changes the ranking.

If browsing is unavailable, record exact pending queries and continue with
local measurements; do not invent external support.

## Stop Rules

Stop when:

- source classes converge and a local measurement path exists;
- current asset/code measurement rejects the idea;
- results repeat unsourced folklore;
- no local anchor appears after terminology and language expansion;
- further search cannot alter the top candidates or requested reserve.

External research may create `ESTIMADO` or `REQUIERE BUILD` candidates. Only
current local counts/builds create `EXACTO`.
